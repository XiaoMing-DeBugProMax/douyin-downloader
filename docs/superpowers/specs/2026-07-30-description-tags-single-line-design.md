# 解析结果文案与标签单行展示设计

- 状态：用户已批准
- 日期：2026-07-30
- 范围：解析结果卡片的前端展示

## 1. 目标

将解析结果中的作者标题、普通文案和视频标签分别展示为三行，使结果卡片高度稳定、
信息层次清楚。超出可用宽度的内容不换行，以省略号隐藏溢出部分。

## 2. 展示规则

- 作者标题保持当前标题位置，固定占一行。
- 普通文案保持在标题下方，固定占一行。
- 视频标签位于普通文案下一行，固定占一行并使用黄色文字。
- 三行内容超出容器宽度时均显示省略号。
- 每行通过原生 `title` 提示保留完整文本，便于鼠标悬停查看。
- 普通文案为空时显示“暂无文案”；标签为空时隐藏标签行，不保留空白。
- 页面使用 `textContent` 和 `title` 属性呈现外部文本，不使用 HTML 注入。

## 3. 标签拆分规则

拆分只发生在前端展示阶段，不改变后端返回的原始 `description`，也不影响下载文件名。

- 只提取文案末尾连续出现的一个或多个 `#标签`。
- 标签之间允许包含空白。
- 正文中间出现、且后面仍有普通文字的 `#内容` 不拆分。
- 拆分后移除普通文案末尾多余空白，标签按原有顺序显示。
- 无法可靠识别时保留完整原文作为普通文案，不生成标签行。

示例：

```text
原文：双朵组合到底有多自在？这把阿古朵教学精讲来了 #射手教学 #王者荣耀
文案：双朵组合到底有多自在？这把阿古朵教学精讲来了
标签：#射手教学 #王者荣耀
```

## 4. 实现边界

- 在 `app.js` 中增加独立的展示拆分函数，并分别填充文案和标签元素。
- 在 `index.html` 中增加标签行。
- 在 `styles.css` 中为作者、文案和标签应用单行省略规则，并为标签设置主题兼容的黄色。
- 保持 FastAPI 响应模型、解析领域模型、内存存储和下载流程不变。

## 5. 验证

- 单元测试覆盖：无标签、单标签、多标签、正文中间 `#内容`、空文案。
- 页面测试验证作者、文案和标签分别渲染，使用安全文本赋值。
- 浏览器测试验证三行不会换行，溢出时出现省略号，标签缺失时不占位。
- 验证三种主题及窄屏布局下黄色标签仍清晰可读。
