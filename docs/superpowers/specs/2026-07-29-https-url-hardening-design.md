# HTTPS 抖音链接与畸形 URL 加固设计

## 目标

收紧现有单视频解析入口：

- 只接受 `https://` 抖音链接。
- 将所有可预见的 URL 结构解析异常转换为稳定、可读的客户端错误。
- 保持现有抖音主机白名单、逐跳重定向校验、五跳上限和本机安全边界不变。

## 范围

本次只修改分享链接的提取与校验，以及对应自动化测试和用户说明。
不增加第三方依赖，不改变视频解析、下载、会话、控制窗口或内容合规策略。

## 输入分类与错误契约

| 输入 | HTTP | 错误码 | 页面提示 |
| --- | ---: | --- | --- |
| 合法 HTTPS 抖音链接 | 继续解析 | - | - |
| 合法 HTTP 抖音链接 | 400 | `UNSUPPORTED_URL` | 仅支持 HTTPS 抖音公开视频链接。 |
| HTTPS 非抖音链接 | 400 | `UNSUPPORTED_URL` | 目前只支持抖音公开视频。 |
| 含 HTTP(S) 特征但 URL 结构畸形 | 400 | `INVALID_INPUT` | 链接格式不正确，请粘贴有效的 HTTPS 抖音分享链接。 |
| 不含可识别 URL 特征 | 400 | `INVALID_INPUT` | 没有识别到抖音链接，请粘贴完整分享文案。 |

“结构畸形”包括 URL 拆分、主机读取或端口读取期间发生的格式异常，以及空主机、
无效端口、括号不匹配和会触发 Unicode 主机规范化异常的输入。包含用户名或密码、
非默认端口以及非白名单主机仍属于不支持的 URL。

## 实现设计

校验继续集中在 `url_resolver.py`，不把 URL 规则分散到 API 或页面：

1. 提取阶段区分“完全没有 HTTP(S) 特征”和“看起来像 URL 但结构无效”。
2. URL 拆分、`hostname` 和 `port` 访问都位于统一异常边界内；任何格式类
   `ValueError` 都转换为 `INVALID_INPUT`，不允许冒泡为 HTTP 500。
3. 完成结构解析后，先识别白名单抖音主机，再拒绝该主机上的 HTTP 协议，
   从而为 HTTP 抖音链接提供专用提示。
4. 仅 HTTPS、无凭据、默认 443 端口且主机在现有白名单中的入口链接可以继续。
5. 短链接每次重定向仍调用同一个校验函数，因此 HTTP、畸形或非白名单跳转会在
   发出下一次请求之前被拒绝。

前端继续显示服务端返回的 `error.message`，不增加重复的客户端 URL 规则。

## 测试

采用测试先行方式覆盖：

- 现有 HTTPS 分享文案和作品长链接继续通过。
- 所有允许入口主机的 HTTP 链接被拒绝，并返回 HTTPS 专用提示。
- HTTPS 快手或其他非抖音主机继续返回抖音专用限制提示。
- 括号不完整、空主机、非法端口和异常 Unicode 主机统一返回畸形 URL 提示。
- 短链接重定向到 HTTP、畸形或非白名单目标时，在请求目标前拒绝。
- 无链接文本保留现有提示。

完成后运行 URL 聚焦测试、完整 pytest、Ruff、严格 Mypy、JavaScript 语法检查和
`git diff --check`。

## 非目标

- 不判断视频版权、违法性或平台内容合规性。
- 不支持快手等其他视频平台。
- 不增加批量下载、私密视频、登录态或访问控制绕过。
- 不改变媒体 CDN 地址的独立 HTTPS 白名单校验。
